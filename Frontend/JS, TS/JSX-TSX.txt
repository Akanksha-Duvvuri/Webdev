 1.JSX - javascript XML (extensible markup language - like HMTL, you can use tags etc etc but this also helps describe what the data actually does instead of just displaying it) and this JS XML is an XML like syntax extention used in JS frameworks like React.
    So JSX basically helps you write HTML like code directly within your JS files, or basically HTML + JS.
    CSS is written separately and can be imported to the respective file

    A framework is a pre-built foundation that provides the structure, tools, and funtionality required to build applications. 

    Purpose of JSX - it makes writing the user interface (UI) easier instead of manually writing HTML and JS separately. 

    Browser can not read the JSX directly, a tool like Babel (JS complier - transpiles (source to source compile - translate source code written in one language to an equivalent source code in another language or a diff version of the same language)) converts it into the standard JS functions, etc etc and this is read and understood by the browser

    Now TSX - a file extention and syntax used to write React components using Typescript (combines ts with JSX) - helps developers directly write their HTML like UI along with their components. 

    Why TSX over JSX? - this is because TS compiler checks for component props (properties - read only objects (a DS that stores data as a collection of key-value pairs) that are used to pass data from a parent component to a child component), state, and UI elements for type errors before your code runs in the browser


2. imports and exports in tsx files - statements used to share code like react components(independent, reusable pieces of code - they are like functions but return HTML), functions, objects and types between diff files. 
any file containing a top level import or export is considered a module. A file wo top level imports and exports are treated as a script whose contents are available in the global scope (and hence are modules as well)
Modules are executed within their own scope, so functions should be explicitly exported to be used in other files. 
    Named exports - share multiple items from a single file, import names must match the exported names
    Default exports - if a file contains only one primary component, import name can be arbitrary
    Barrel exports - re exporting basically

3. Return - a statement that specifies the UI that the component should display on the screen.

4. use client directive(an official order to do something) is a react feature used to declare a boundary between server and client components within frameworks. 
It is needed because it signals that the module and all the files imported into it (cascade effect) should be treated as a client side JS capable of running in the browser. 

React has a default environment which is the RSC (react server components), so using client switches the environment from server side to the client side.
This does not disable SSR (server side rendering), it just tells the framework to send the JS so that the browser can interpret it and make it functional and interactive.  

This creates a client component. If we remove it, the page can still be rendered on the server and gets sent as HTML but it wont be interactive as JS wont be sent.

9. useEffect - it basically takes care of the side effects (effects that are apart from rendering the UI, A side effect is any operation that interacts with something outside the component's rendering process.) ex, fetch data from an API, start a timer, update the title, access localStorage etc etc

React renders the UI and then does some extra work after rendering (fetching, calling, etc etc this is what useEffect does)

useEffect(() => {
    logic
}, []);  <---- dependency array 

the dependency array makes the effect run only once, right after the initial render, you can also use the hook without the dependency array for it to run everytime you click on it

when you have some value in the dependency array - the effect runs after the initial render and re runs whenever any value inside the array changes 

const [count, setCount] = useState(0);

useEffect(() => {
    console.log("Count changed");
}, [count]);

click a button - setCount becomes 1 - count changed so the effect runs

without a dependency array - runs after every single render of the component

13 - closure - a function that remembers variables from its outer scrope even after the outer function has finished executing

Each execution creates a new scope, and each returned function keeps a closure over the variables from its own scope.

A scope is simply:
The region of code where a variable exists and can be accessed.

a function's local variables are destroyed when the function finishes executing. However, if an inner function still references those variables, JavaScript keeps them alive. This preserved state is called a closure.

a and b have separate closures. Calling a() increments its own count, while b() starts with a fresh count of 0 because it was created by a different call to outer().

14.  onClick={handleClick} -> passes the function itself to react so you dont need the parenthesis again

onClick={handleClick} passes a function reference, while onClick={handleClick()} executes the function immediately. React expects a function to run when the event occurs, not the result of calling the function during render.

main reason for the arrow function is to delay execution until the click happens.

When you see:

onClick={something}

ask yourself:

Is something a function reference?

Good:

onClick={handleClick}

Good:

onClick={() => handleClick("Akanksha")}

Bad:

onClick={handleClick()}

Bad:

onClick={handleClick("Akanksha")}

because both execute immediately.

15. Conditional Rendering - 
&& is used because it provides a concise way to render something only when a condition is true.

use a ternary when I need to choose between two different UI outputs. I would use && when I only want to render something when a condition is true and render nothing otherwise.

prev represents the most recent state value maintained by React. Using prev => prev + 1 is safer because state updates can be batched or queued, so relying on the current count variable may use a stale value.
